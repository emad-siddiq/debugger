# 05 — Prove it on merkle: three-pass simulation + the interactive walkthrough

> Workstream 5 of the [master plan](00-master-plan.md). Deliverables: a scripted headless pass,
> an automated in-IDE pass, and — the user-facing artifact — **an interactive walkthrough
> checklist** (`docs/plans/walkthrough.md`, generated by WO-21) that hand-walks you through the
> entire merkle UX from first launch, exercising every Burrow tool, and flushing out anything
> that doesn't render, doesn't populate, or exists twice.
>
> Everything here is grounded in `~/Projects/merkle/infra`: `./merkle --start`,
> `infra/test/nodewatch.http`, `infra/test/nodewatch.postman_collection.json`,
> `infra/test/mock/{seed.sh,backfill.sql,e2e.sh}`, `infra/test/env/*`, the six tutorials in
> `infra/test/tutorials/`, and the cluster lab in `infra/test/cluster/` (minikube).

---

## Part 1 — Technical summary (for product review)

Three passes, in strictly increasing realism. Each has a fixed scenario matrix, a written
expected-result per step, and an evidence bundle. Nothing advances to the next pass until the
current one is green, because each pass reuses the previous one's fixtures.

- **Pass 1 — scripted, no IDE.** Prove the *stack* is healthy so every later failure is a
  *tooling* failure: `./merkle --start`, seed, smoke, all ~56 endpoints via the Postman
  collection, teardown/restart idempotence. Runs headless in CI-style.
- **Pass 2 — automated through Burrow.** Playwright over CDP (the `launch` skill) drives the
  actual IDE: every rail view populates, the render sweep is 0-blank, breakpoints bind and hit
  in both languages, a DB write lands and shows in the Data grid, the agent panel answers with
  context. This is the regression net.
- **Pass 3 — the interactive walkthrough (you).** The deliverable checklist below: sit down at
  Burrow like a new-but-traditional SWE, follow numbered steps from cold start through login,
  component rework, API, DB, full-stack breakpoints, chaos. Every step states *do this → you
  should see this → tick or file*. Includes deliberate "redundancy hunts" — steps that make you
  do the same job two ways so duplicated surfaces get noticed and killed.

Auth0 (real login, tutorial 04) is included but flagged optional; the default path uses
`VITE_SKIP_AUTH=1`. The minikube chaos lab is the closing optional act.

## Part 2 — Details for the implementing agents

### 1. Fixtures — one seeded world for all passes

One make-style entry (`infra`-driven, no new infra):

```bash
cd ~/Projects/merkle/infra
./merkle --start                       # db + api + web, Auth0 off, Mode B
bash test/mock/seed.sh                 # the 8-node fleet + orgs
psql "$DB" -f test/mock/backfill.sql   # metric history so charts have lines
```

Canonical world: default org `…0001`, 8 nodes, seeded alerts, metric history ≥ 24 h. Every
expected-result below refers to this world; if seeds change, regenerate the expectations in the
same change.

### 2. Pass 1 — stack truth (scripted)

Script: `debugger/docs/plans/scripts/pass1.sh` (new, checked in; plain bash; each step prints
`PASS/FAIL step-name`). Steps:

| # | Step | Green means |
|---|---|---|
| 1 | `./merkle --start` then `curl :8080/healthz`, `curl :5173` | both 200 within 60 s |
| 2 | seed + backfill (idempotent — run twice) | second run exits 0, row counts unchanged |
| 3 | `bash infra/test/smoke.sh` | its own PASS line |
| 4 | Endpoint sweep: run the Postman collection with newman (or `infra/test/mock/e2e.sh` if that's its job — read it first) against `:8080` with the local env file | every request 2xx/4xx-as-documented; write the per-route table to `pass1-endpoints.md` |
| 5 | Ingest door: `POST /ingest` with `X-API-Key` per tutorial 02 | 202/200 + row visible via `GET /api/nodes/{id}/metrics` |
| 6 | `./merkle --restart-api` mid-traffic | recovers < 5 s, no orphan processes |
| 7 | `./merkle --down && --start` | world intact (db survives by design) |

### 4. Pass 3 — **the interactive walkthrough** (the user's deliverable)

**WO-21 produces `docs/plans/walkthrough.md`** in exactly this shape — a checkbox document you
follow top to bottom. The skeleton below is normative: the WO fills in precise values (line
numbers, seeded names, screenshots) by actually performing it once against the seeded world,
then freezes it. Format per step:

```
- [ ] NN. **Do:** <one action, one surface>
      **See:** <the one thing that proves it worked, with the exact value from the seeded world>
      **If not:** <the file to look at / the fix WO to reference>
```

#### Act 0 — Cold start (5 min)
1. Launch **Burrow from Launchpad** (`06` WO-19). *See:* merkle opens as the workspace, native
   title strip, 7 rail icons, no top row, no sign-in anywhere.
2. `⌘⌥D`. *See:* Agent panel slides in on the right, one session tab dot; `⌘⌥D` again closes it.
3. Run view → **Debug Full Stack**. *See:* three tier rows go green in order (db → api → web);
   Chrome opens on `http://localhost:5173/watch/app/`.

#### Act 1 — First contact with the app (10 min)
4. In the opened app: the overview shows the **8 seeded nodes**. *(Auth path option: if running
   Mode C, this is where you enter your password at the Auth0 wall — see Act 6.)*
5. Click one node → dashboard renders charts with **≥ 24 h of history** (the backfill).
6. Redundancy hunt №1: count the ways you can see "node list" (app page, API view `GET
   /api/nodes`, Data view `nodes` table). All three must show the *same 8 rows* — note anything
   that disagrees or any fourth surface that duplicates.

#### Act 2 — Components: inspect, rework, see it live (25 min)
7. Rail → **Components**. *See:* status row `dev server: :6099 live`; gallery grouped by folder.
8. Isolate `Badge`. *See:* explorer still visible; source left, CSS below-left, preview right;
   props panel with provenance chips.
9. Isolate `DataTable`. *See:* **three plausible rows render** (type-synthesized); the Badge
   tabs closed themselves (tab hygiene); ≤ 3 tool tabs total.
10. Rework: change `--badge-*` token or a tone colour in `Badge.css`, save. *See:* preview
    updates < 1 s; **Breakpoints tab** (responsive) lists the stylesheet's media queries;
    click `→ 768px` — the stage jumps to tablet width.
11. Toggle `prod-css`. *See:* the component against production-built CSS; any drift = file it.
12. **Pick** in the app preview → click the badge on a node row. *See:* editor reveals the
    exact `Badge.tsx` line; ⛶ full-screens the preview; **Esc** returns.
13. Agent: select the tone-mapping lines, `⌘⌥I`. *See:* ≤3-bullet insight citing
    `lib/statusColor.ts`, memory chip `design.yaml`.

#### Act 3 — Follow one click all the way down (20 min)
14. API view → arm a breakpoint on `GET /api/nodes` (symbol-anchored). Editor: breakpoint in
    `frontend/src/api/client.ts` at the `request<T>` headers line (tutorial 03's spot).
15. In the app, reload the fleet page. *See:* **stops in `client.ts` first** — inspect the
    `X-Request-Id` header being attached; continue.
16. *See:* **stops in the Go handler** — right dock shows Frames/Inspector; find the same
    request id in the slog line; step to the SQL call; continue.
17. *See:* the Request Trace joins frontend netlog ⨝ backend slog on that id — one row, two
    worlds.

#### Act 4 — Create something and watch it land in the DB (15 min)
18. HTTP workbench: open `infra/test/nodewatch.http`, run the **create alert rule** request
    (name it `walkthrough-rule`). *See:* 201 in the response pane.
19. Data view → `alert_rules` table refresh. *See:* the row with `walkthrough-rule`, and the
    app's alerts page now lists it too. Redundancy hunt №2: the native grid vs pgAdmin — open
    the same table in both; the native grid should be your default, pgAdmin only for ERD/plans.
20. Try a `DELETE` in the grid with writes locked. *See:* refused with the lock state shown;
    unlock, delete, re-seed if desired.
21. Tab-isolation check (`02 §6`): rail-hop Data → Components → API → Data. *See:* at each stop
    the tab bar holds only that tool's surfaces (≤3) plus anything you pinned or edited — no
    leftover grids/response panes from the previous tool; the grid you closed reopens from the
    Data view in one click.

#### Act 5 — Tests as a lab (10 min)
22. Run view → Tests → run the backend package that owns alert rules. *See:* the **Test Lab**
    tab: failures-first output, durations; open coverage → gutters paint in the handler file.
23. Break the handler deliberately (return early), re-run failed only. *See:* red diff-style
    failure; fix; green. Undo.

#### Act 6 — Identity, optional (20 min)
24. Flip Run view Debug Config → **Auth0 ON** (config from `infra/test/env/backend.auth0.env`);
    restart the backend tier; open the app fresh. **Do:** enter your password at the Auth0 wall.
    *See:* a JWT-bearing request; breakpoint in the middleware chain shows the org being
    provisioned (tutorial 04's flow) — then flip back to Auth0 OFF.

#### Act 7 — Chaos, optional capstone (30 min)
25. `infra/test/cluster/` lab via the simulator: 2-replica backend on minikube, kill the
    leader, watch the app stay up and the topology view reflect the failover.

#### Exit criteria
26. Zero unticked boxes, or each untick filed as a defect WO with its Act number. A
    **redundancy list** (things seen twice) reviewed and either justified in a sentence or
    scheduled for deletion.
